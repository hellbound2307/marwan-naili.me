Agentic systems

Capability sandboxing for on-device agents

Containment design for a system that lets a model execute code: bind-mount discipline, declared-permission plugins, a network allowlist enforced below the application, and escape testing against the boundary itself. Includes a self-audit that confirmed a privileged bridge crossing the guest boundary — and the fixes that closed it.

Sandboxing · permission models · network enforcement · boundary testing

Degradation behaviour in long-horizon agents

Observed failure modes when a model runs unattended across many turns: text-repetition collapse, empty responses returned as success, hard length walls, and tool loops. Each detected as a distinct class with an explicit exit rather than a retry that burns budget silently.

Failure analysis · loop detection · agent-loop instrumentation

Sustaining a fork against upstream drift

Operational study of maintaining a divergent platform fork: build verification on-device rather than trusting CI, expectation-gated releases, and a debt ledger of files too large to keep editing. Written up because the failures are more instructive than the successes.

Platform engineering · release discipline · technical debt tracking

Applied ML & evaluation

Abstention as a first-class retrieval output

A retrieval system rebuilt so that "the corpus does not contain this" is a valid and common answer. Separate indexes for keyed lookup data and conceptual corpora so a large catalogue cannot poison concept queries; IDF-weighted coverage instead of term counting; a higher bar when any query term is absent from the corpus entirely. Measured on a hand-built gold set — and checked for robustness across the threshold range, because a spike at one value is overfitting, not accuracy.

RAG · IDF weighting · abstention calibration · recall/MRR evaluation

Small-model routing and needle-retrieval

Measuring whether cheap specialist models can be routed instead of one general model — routing ablations against a single-model baseline — plus adversarial long-context retrieval tests to find where a fine-tuned small model stops holding facts. Training runs on constrained hardware, so cost is a real constraint, not an abstraction.

SFT · routing · adversarial evals · on-device inference

Wormlab — the capability floor of small models in cyber tasks

Open question. Public claims that AI-driven worms are feasible with small free models test a single, deliberately undisclosed model size and stop there. Untested: the quantitative floor, the curve rather than the point, micro-policies versus language models, and payload execution versus rhetoric. I am building the sweep — size against task fitness, below single-GPU scale — with a publication plan attached, because a headline that cannot be reproduced is not a result.

Security measurement

DarkTortilla RAT — Telegram exfiltration channel

Static and dynamic analysis of a commodity Android RAT's exfiltration path: payload extraction, protocol reconstruction from recovered code, and derived indicators of compromise. Malicious samples were handled in isolation; no live infrastructure was contacted.

Reverse engineering · threat analysis · public

Evidence grading in data-breach claims

How to tell a live leak from a re-upload. Working standard applied to a public breach claim: trace the original actor and date independently, check whether the claim matches a re-post, verify the host is a real affected organisation, and state plainly what remains technically unverified. Confidence and provenance travel with every claim.

OSINT · verification · provenance discipline

Internet-facing critical infrastructure census · ongoing

Passive-first measurement of Algerian critical-sector exposure — energy, water, ports, rail, telecom edge — using public search indexes, DNS and historical records, certificate transparency, archived pages and published technical documentation. The deliverable is a chain, not a port number: observation → attribution → technology → known vulnerability → how long it has been observable. Non-intrusive by construction. Disclosure to the responsible party and to the regulator first.

Principles

  • Verify the targetA passing command proves the mechanism, not the objective. The state after the action is the evidence.
  • Keep the layers apartObserved, reported, inferred and unknown are distinct. A report is not promoted to a fact because it is convenient.
  • Prefer the smallest changeIncremental beats elegant. A verified rough system is worth more than a clean one that was never deployed.
  • Say no earlyScope without written authorization means no work. The line is cheaper to hold before you cross it.
